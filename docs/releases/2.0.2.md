# KnowNext.ai 2.0.2

KnowNext.ai 2.0.2 fixes a production GitHub authentication fallback that could show the internal development account as connected after the user attempted GitHub login while remote GitHub OAuth was unavailable.

## What Changed

- Installed Windows and Android builds no longer accept the internal development GitHub placeholder account.
- Any persisted development GitHub auth marker from 2.0.1 is removed automatically when the app reads auth status.
- Projects connected to GitHub remain editable with local history while remote GitHub access is unavailable.
- The GitHub login dialog no longer polls a mock device flow in production when the runtime reports GitHub remote auth is not configured.
- Release validation now scans the production frontend bundle for development GitHub mock strings.

## Validation Required Before Publication

- `pnpm version:check`
- `pnpm release:check`
- Windows Tauri release build with updater signing configured
- Android release build with Android signing configured
- Manual Windows update acceptance from 2.0.1 to 2.0.2, including cleanup of the internal development GitHub placeholder account
- Manual Android update acceptance from 2.0.1 to 2.0.2
- GitHub release asset verification for MSI, NSIS, Windows signatures, `latest.json`, Android APK, and `android-latest.json`

## Known Limitations

- Real GitHub remote synchronization remains replaceable/mock-backed until Rust GitHub credentials, permissions, conflict handling, and recovery flows are validated end to end.
- AI provider execution remains replaceable/mock-backed until provider credentials, privacy rules, and runtime routing are validated end to end.
- Document previews and exports are Rust-managed and currently best-effort for formats that require complex conversion.

Do not publish this release if packaged Windows or Android builds fail, updater signing is unavailable, Android signing is unavailable, critical manual acceptance fails, or update manifests do not resolve to `2.0.2`.
