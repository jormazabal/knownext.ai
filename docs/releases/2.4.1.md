# KnowNext.ai 2.4.1

KnowNext.ai 2.4.1 is a save-state and synchronization polish release focused on making document status less noisy, more accurate and easier to act on across desktop and Android installs.

## What Changed

- Document drafts are now compared by canonical Markdown hashes so a draft only exists when it differs from the saved file on disk.
- Reopening a document no longer resurrects stale formatting changes after a user edits and returns to the original content.
- The document footer now prioritizes the user's next action: unsaved edits show save/discard controls, while GitHub synchronization appears only after the document is saved.
- Automatic post-save local history and GitHub synchronization now displays `Sincronizando` while the app is working, instead of showing a premature manual sync button.
- GitHub sync errors still surface as actionable states with manual recovery, while normal automatic sync stays quiet.
- The version history drawer now lists the newest entries first, uses compact one-line records, groups entries by natural date ranges, and loads older history incrementally.
- AI conversation bubbles that refer to a document now include a compact document link so users can open the referenced file directly.
- Project tree filters for all files, Markdown, images and support files now stay selected even when the active document is not part of the current filter.

## Validation Required Before Publication

- `pnpm version:check`
- `pnpm release:check`
- Windows Tauri release build with updater signing configured
- Android release build with Android signing configured
- Manual Windows acceptance: edit a document, undo the edit, close and reopen it, and confirm no stale draft or save prompt returns.
- Manual sync acceptance: save with automatic GitHub enabled and confirm the footer shows `Sincronizando` until sync completes or an error appears.
- Manual history acceptance: open the history drawer, confirm newest-first ordering, date separators and incremental loading.
- Manual AI acceptance: ask the assistant to modify or reference a document and confirm the bubble footer opens that document.
- Manual tree acceptance: switch between `Ver todo`, `Solo Markdown`, `Solo imágenes` and `Solo archivos` while a document of another type is active and confirm the selected filter remains active.
- Manual Android smoke/update acceptance from 2.4.0 to 2.4.1, including offline document opening and editing.
- GitHub release asset verification for MSI, NSIS, Windows signatures, `latest.json`, Android APK, and `android-latest.json`.

## Known Limitations

- GitHub remote synchronization still depends on a valid GitHub account, repository access and network availability; unavailable remotes pause automatic sync while local history remains usable.
- Draft recovery is content-based for Markdown and does not attempt semantic normalization beyond canonical line endings and trailing newline handling.
- Advanced restore flows for related assets remain explicit; restoring a document version does not automatically select additional assets.
- Agentic web research remains unavailable; local guided agentic limits are exposed but external web investigation is intentionally not active.

Do not publish this release if packaged Windows or Android builds fail, updater signing is unavailable, Android signing is unavailable, critical manual acceptance fails, or update manifests do not resolve to `2.4.1`.
