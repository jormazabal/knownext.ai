# KnowNext.ai 2.6.0

Meeting recording and the updated OpenAI catalogue are now integrated into the local workspace.

## What changed

- Windows system-tray recording window with microphone and selected application-audio output, independent signal meters, pause, resume and stop.
- Start recording from a project folder or root to create the transcript there; start from the tray/application to choose project, folder and name after stopping.
- GPT-Transcribe file transcription without speaker identification, using the OpenAI key already configured on each device.
- Saved recordings, recovery after interruption, per-fragment checkpoints, explicit handling of uncertain API results, local playback and seven-day audio retention after successful Markdown creation.
- Native Android microphone foreground service and notification controls, plus recoverable background transcription fragments.
- One OpenAI catalogue shared by Rust and TypeScript; new defaults for text, vision, images and meetings, with existing selections preserved and incompatible/retired models blocked.
- USD tariffs and dated ECB conversion to EUR; historical costs without verifiable conversion remain separate.
- Correct folder right-click menus, collision-safe document names, hidden recovery metadata and a separate development WebView profile.

## Verification

Automated frontend/Rust release checks and signed Windows/Android builds are required by the release workflow. The Windows debug application has also completed real WASAPI loopback tests with synthetic Spanish speech, including pause exclusion, shared state between tray and main window, deferred destination, cancellation without data loss, filename collisions and opening the generated Markdown.

The user requested publication so the next tests can take place in real meetings on the installed version. These meeting/device acceptance tests are explicitly pending; see [recording validation](../development/recording-validation.md) and [manual checklist](../development/manual-test-checklist.md).

## Known limitations

- No speaker diarization or word/audio synchronization.
- Android records the microphone, not calls or Teams application audio; devices must support 24 kHz PCM input.
- Long meetings, headset/microphone combinations, Android screen-lock/background behaviour and Basque/bilingual transcription still need real-device acceptance.
- Audio cleanup runs while the app is open and removes local copies only. Unknown transcription results may incur additional cost if retried.
- Cost estimates are not invoice totals. EUR-budgeted research needs a recent ECB reference and a retry when that reference becomes available.

## Distribution

Windows updates use the signed MSI via `latest.json`; NSIS remains an alternative installer. Android uses the existing signing identity and `android-latest.json`. Publishing requires MSI, NSIS, both updater signatures, Windows/Android manifests and the signed arm64 APK. Signing identities remain unchanged.
