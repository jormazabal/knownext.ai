# KnowNext.ai 2.5.0

KnowNext.ai 2.5.0 is a professional research and workspace usability release. It turns investigation into a first-class AI capability, improves long-running job feedback, refines the editor and project tree, and keeps Windows and Android update behavior aligned.

## What Changed

- Added a single `Investigación` capability in the prompt `+` menu. The app now prepares an adhoc plan, proposes candidate sources and report length, waits through a pausable 60-second countdown, and then creates a new reviewable Markdown report.
- Added the base `Informe de investigación` skill and the `knownext-research` Rust runtime module for strategy, query batches, source ranking, evidence extraction, coverage analysis, synthesis, report writing and verification.
- Research jobs now show live activity, elapsed time, source/evidence counters, token and estimated-cost metrics, stalled-job feedback, retry support and cancellation confirmation.
- Research context is now compacted and processed in bounded batches so later AI calls do not resend all accumulated source material and are less likely to exceed provider context windows.
- Research settings are reduced to product-level controls: maximum cost per investigation, diagrams enabled and images enabled. Web research remains required for the research feature.
- The prompt `+` menu is more compact and stable, with grouped context/capability actions, hover descriptions and a controlled `Crear` submenu for images and diagrams.
- AI conversation bubbles now keep document links, timestamps and copy actions in compact metadata below each bubble, with time separators and incremental loading for older messages.
- The Markdown workspace now includes a raw Markdown toggle near zoom, improved heading/image spacing, reduced list indentation, aligned numbered lists and bullets, and more polished Markdown source rendering.
- The project tree now follows a clearer interaction model: one click focuses, double click opens, chevrons expand/collapse with one click, and context menus reposition so they are not clipped by the viewport.
- Permanent IA and Notas tabs are preserved when closing all document tabs.
- Android update checks now avoid showing raw fetch failures for expected unavailable/no-update states.

## Validation Required Before Publication

- `pnpm version:check`
- `pnpm release:check`
- Windows Tauri release build with updater signing configured
- Android release build with Android signing configured
- Manual research acceptance: start an investigation, review the plan, pause the countdown, edit sources/length, run it, confirm live metrics update, and confirm the created report opens automatically.
- Manual research failure acceptance: force missing provider/web configuration and confirm no partial document is created.
- Manual AI menu acceptance: open the prompt `+` menu, hover each option, open/close `Crear`, and confirm descriptions/submenus stay synchronized.
- Manual AI conversation acceptance: confirm document links, timestamps, copy actions, time separators and `Mostrar más` behavior.
- Manual editor acceptance: verify raw Markdown toggle, source rendering, H2 spacing, image margins, bullet/number alignment and permanent IA/Notas tabs.
- Manual project tree acceptance: verify single-click focus, double-click open, chevron one-click expand/collapse and viewport-aware context menus.
- Manual Android updater acceptance: use `Buscar actualizaciones` on Android and confirm unavailable/no-update cases are shown as normal product states, not raw fetch errors.
- GitHub release asset verification for MSI, NSIS, Windows signatures, `latest.json`, Android APK and `android-latest.json`.

## Known Limitations

- Research requires configured OpenAI access and web availability. If provider access is missing, the job fails before creating a report.
- Research cost is estimated from provider usage records and may differ slightly from final billing.
- Generated research reports are reviewable drafts; users should verify critical citations before relying on conclusions.
- GitHub synchronization still depends on account, repository permission and network availability; unavailable remotes pause automatic sync while local history remains usable.

Do not publish this release if packaged Windows or Android builds fail, updater signing is unavailable, Android signing is unavailable, critical manual acceptance fails, or update manifests do not resolve to `2.5.0`.
