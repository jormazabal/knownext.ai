# KnowNext.ai 0.18.3

## Summary

KnowNext.ai 0.18.3 fixes the recovery path for GitHub credential failures so editors can resolve a broken repository connection from inside the application.

## Product Changes

- Added an explicit credential problem state in project configuration when GitHub rejects the saved access credentials.
- Added `Revisar credenciales` as the primary recovery action for affected GitHub projects.
- Added `Cerrar sesión` as a secondary action so users can disconnect the current GitHub account and connect another one.
- Kept the technical Git error visible as supporting detail while giving the user clear next actions.

## Technical Notes

- The GitHub login flow now starts a fresh device authorization when credential review is requested, even if a previous session still exists locally.
- Project synchronization status is refreshed after GitHub login or logout so stale credential errors are cleared or re-reported immediately.
- Added focused frontend coverage for the invalid-credentials state in the project edit modal.

## Validation

- `pnpm --filter @knownext/desktop test -- CreateProjectDialog`
- `pnpm --filter @knownext/desktop build`
- Browser validation on `http://127.0.0.1:1420/` for opening the project edit modal after the change.

## Distribution

The GitHub release for `v0.18.3` must include the NSIS installer, MSI installer, both updater signatures, and `latest.json`. The published `latest.json` must resolve to version `0.18.3` and keep `windows-x86_64.url` pointing to the MSI artifact.
