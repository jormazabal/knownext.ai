# KnowNext.ai 0.18.0

## Summary

KnowNext.ai 0.18.0 evolves project history and synchronization into a simpler product model: local files, local Git history, or local Git plus GitHub, with manual or automatic synchronization behavior.

## Product Changes

- Replaced scattered history and GitHub choices with three explicit project protection levels.
- Added a synchronization mode control so projects can stay manual or synchronize automatically when supported.
- Improved project creation and editing flows so an existing local project can evolve toward local Git or GitHub without recreating it.
- Simplified the document footer so users see one clear next action: OK, Guardar, Sincronizar, Actualizar, or discard pending draft changes.
- Scoped synchronization state to the active document, avoiding project-wide status messages when the user is working on one file.

## Version History

- Reworked the history panel as a compact version selector with short dates and current-version highlighting.
- Moved historical content and comparison into the main document workspace.
- Added a formatted read-only view for historical Markdown content instead of showing raw Markdown syntax.
- Added a two-column diff with aligned rows, independent line numbers, and icon-only view controls.
- Added informed restore confirmation, including draft handling when pending edits exist.

## Technical Notes

- Added document sync API contracts and backend services for document-level synchronization state.
- Extended project, document, version, and sync schemas to carry the new product model.
- Updated frontend API modules and shared domain types for synchronization and version preview flows.
- Reused a shared readonly Milkdown viewer for release notes and historical document content.

## Validation

- `pnpm --filter @knownext/desktop build`
- `pnpm --filter @knownext/desktop test -- DocumentStatusBar`
- `python -m pytest backend/tests/test_api.py`
- Browser validation on `http://localhost:1420/` for project configuration, document footer states, history preview, formatted version content, two-column diff, restore confirmation, and current-version selection.

## Distribution

The GitHub release for `v0.18.0` must include the NSIS installer, MSI installer, both updater signatures, and `latest.json`. The published `latest.json` must resolve to version `0.18.0` and keep `windows-x86_64.url` pointing to the MSI artifact.
