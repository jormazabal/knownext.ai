# KnowNext.ai 0.18.5

## Summary

KnowNext.ai 0.18.5 fixes GitHub synchronization for projects that use local Git plus GitHub after the user reconnects the GitHub account.

## Product Changes

- GitHub reconnection now resolves the local Git synchronization error that could continue showing `invalid credentials` after GitHub confirmed the device authorization.
- The existing `Verificar conexión` action now exercises Git with the newly connected account using GitHub's expected HTTPS token format.
- Editors no longer need to manage Windows Git Credential Manager manually for this recovery path.

## Technical Notes

- Local Git operations now inject `Authorization: Basic <x-access-token:token>` for GitHub HTTPS remotes.
- This replaces the previous `Bearer` header, which is valid for GitHub API calls but not reliable for Git smart HTTP operations.
- Added backend coverage for the generated Git authentication header.

## Validation

- `python -m pytest tests/test_api.py -k "git_service_uses_basic_token_auth_for_github_https or github_api_project_uses_cache_metadata_and_blocks_remote_conflicts"`
- `pnpm version:check`

## Distribution

The GitHub release for `v0.18.5` must include the NSIS installer, MSI installer, both updater signatures, and `latest.json`. The published `latest.json` must resolve to version `0.18.5` and keep `windows-x86_64.url` pointing to the MSI artifact.
