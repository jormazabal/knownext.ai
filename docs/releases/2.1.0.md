# KnowNext.ai 2.1.0

KnowNext.ai 2.1.0 is a document-editing and image workflow release focused on making AI-assisted Markdown editing feel direct, local-first and product-ready across Windows and Android update channels.

## What Changed

- AI document edits now follow a more Canvas-like interaction model. Safe structured changes are applied directly instead of leaving validation cards in the conversation, including selected text edits, cursor insertions, table insertion, generated images and broader document rewrites.
- The Rust/Tauri AI runtime now returns richer deterministic edit operations, handles cursor context explicitly, supports image generation/insertion operations, and validates document anchors before applying changes.
- Markdown images now render consistently in the visual editor, use local project asset URLs, preserve image proportions, adapt default width to the editor viewport, and support explicit document width when the user chooses one.
- Image insertion and editing now use a product-focused dialog with preview, project image selection, upload/URL paths, alt text, default/custom sizing, replace and delete flows.
- Project images can be dragged from the document tree into the active Markdown document. While dragging over the document, the editor cursor moves to show where the image will be inserted.
- Documents, attachments and images can be dragged from the project tree into the AI prompt as context. Documents and folders can also be moved within the project tree through the controlled Tauri-safe drag workflow.
- Cursor position is sent as hidden AI context when no text is selected; the prompt input no longer shows a visible cursor tag. Selected text still appears as a removable context chip.
- Documentation and validation notes were updated for the new AI editing, image editing and drag/drop acceptance flows.

## Validation Required Before Publication

- `pnpm version:check`
- `pnpm release:check`
- Windows Tauri release build with updater signing configured
- Android release build with Android signing configured
- Manual Windows acceptance: update from 2.0.5 to 2.1.0, open the app, edit a Markdown document, save, reopen, and confirm app data is preserved.
- Manual AI editing acceptance: select text and request expansion, place only the cursor and request table insertion, request an image insertion, and confirm changes are applied directly without review cards when safe.
- Manual image acceptance: insert a project image, confirm it renders without cropping, hover the image to edit it, change alt text/size, replace it, and delete it.
- Manual drag/drop acceptance: move documents/folders in the tree, drag a document to the AI prompt as context, and drag an image from the tree into the active document at the intended cursor position.
- Manual Android smoke/update acceptance from 2.0.5 to 2.1.0, including offline operation without a workstation app or external product service running.
- GitHub release asset verification for MSI, NSIS, Windows signatures, `latest.json`, Android APK, and `android-latest.json`.

## Known Limitations

- AI provider execution requires locally stored OpenAI credentials and should be manually accepted with real credentials before relying on provider workflows.
- GitHub remote synchronization still requires a valid GitHub account and repository permissions; when access is missing, remote sync remains paused while local history stays available.
- Agentic web research remains unavailable; local guided agentic limits are exposed but external web investigation is intentionally not active.
- Document previews and exports are Rust-managed and currently best-effort for formats that require complex conversion.

Do not publish this release if packaged Windows or Android builds fail, updater signing is unavailable, Android signing is unavailable, critical manual acceptance fails, or update manifests do not resolve to `2.1.0`.
