# Avance97 · Extraer contenido de una copia con registro incompleto

[Reporte visual](avance-97.html).

F04/T02/T03/T14: el centro de recuperación permite revisar y extraer Markdown legible o una nota manuscrita estructurada compatible de una carpeta privada cuyo registro no se ha podido comprobar. La fila Apartadas mantiene su error y añade «Revisar contenido sin registro»; no habilita recuperación directa en proyecto ni atribuye proyecto, fecha, papel en un conflicto o intento confirmado. El registro puede faltar, estar dañado, no coincidir o tener un formato futuro. Se conserva sin interpretarlo como una versión antigua ni repararlo.

recovery_incomplete.rs lee solo copy.json y la huella opaca del manifest.json opcional de una carpeta recovery-* conocida. Límites8MiB de copia,16KiB de registro,2MiB de texto Markdown y vista2000 caracteres Unicode; contenido de nota serializado hasta8MiB. Fuente y registro se vuelven a comprobar en la revisión y antes de congelar la entrega; un registro que aparece/desaparece también invalida la revisión aunque el texto sea igual. Carpeta/enlaces no regulares, JSON ilegible, versión futura del contenido, mezcla de markdown y content o contenido fuera de límite se conservan sin extracción. No se pretende recuperar un archivo cuyo texto ya no sea legible. La nota debe superar la validación estructural existente y conservar esquema1; formatos futuros o dañados se conservan sin normalizar ni extraer.

La respuesta de revisión incluye texto acotado, huella de copia, revisión ligada a ubicación y contraparte, tamaño de texto y flags provenanceVerified:false/canRestore:false. No devuelve el documento/proyecto que proclame la copia ni sus campos privados desconocidos. Para Markdown exporta el texto completo y exacto; no incluye imágenes/adjuntos enlazados. Para notas exporta el objeto content completo a .knote, sin reducirlo a texto ni imagen, conservando páginas, muestras de presión/inclinación, texturas, elementos generados, OCR y extensiones documentales desconocidas. No exporta los campos privados del envoltorio de recuperación ni el registro. Las extensiones dentro del propio contenido de la nota se conservan como datos de documento, no se convierten en permisos o instrucciones de ejecución. Puede importarse después por el flujo normal. El original completo, incluidos campos desconocidos, permanece byte a byte en su lugar.

La confirmación de procedencia no comprobada es obligatoria. export_recovery_content es un transporte Tauri limitado a la ventana de trabajo; las reglas residen en storage. Los bytes se congelan en Rust, se elige un archivo nuevo mediante selector nativo y se usa el escritor de recuperación existente, ahora con extensión/MIME explícitos para JSON, Markdown o .knote. El selector usa la extensión del contenido congelado. Creación sin reemplazo y comprobación de bytes; destino dentro del estado privado se rechaza. Android reutiliza su entrega de archivo por ContentResolver con el MIME de Markdown o nota, sin afirmar ejecución de esa ruta. No hay reparación, eliminación, limpieza automática, atribución de recibo ni restauración del estado activo. Repetir contra un destino existente falla y lo conserva.

UI con revisión, advertencia concreta y confirmación junto a acciones fijas. La primera inspección visual mostró la casilla fuera de la parte visible; se movió al pie y se compactaron las acciones, manteniendo revisión y cierre. Un error de entrega retira revisión y confirmación, advierte comprobar el destino y exige revisión nueva antes de otra decisión; no hay reenvío ni consulta que invente un recibo de entrega. Una entrega confirmada también retira la acción. Respuesta tardía de otra copia se ignora. No es un sistema durable de recibos de exportación: una interrupción posterior a la escritura puede requerir comprobar manualmente el destino.

### Notas manuscritas incluidas en el mismo bloque funcional
La respuesta Markdown conserva schemaVersion1. La revisión de nota usa schemaVersion2/kind handwritten-note con resumen de páginas/trazos, sin devolver el objeto de nota completo a React. SDK exige la combinación de formato/tipo y límites; futuros/ambiguos se rechazan. El archivo .knote conserva el valor estructurado del contenido, incluida identidad/fechas internas de la nota como datos, sin atribuirlas a un proyecto de destino. El flujo normal de importación puede reasignar la identidad al importar; esta extracción no lo ejecuta. La presentación muestra un resumen, no una previsualización visual de todas sus páginas.
