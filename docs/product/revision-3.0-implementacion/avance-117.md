# Avance117 · Archivo privado portable del proyecto

[Reporte visual](avance-117.html) · [Definición](bloque-117.md) · [Plan](plan.md).

Se añade una opción explícita al traslado completo de un proyecto. El paquete documental simple sigue siendo la opción inicial. El archivo privado incorpora borradores persistidos (envoltorio exacto y copia editable Markdown/knote), sesiones detenidas asociadas al proyecto (metadatos originales inertes, transcripción conservada y pistas WAV en partes de16MiB), historial Git alcanzable como bundle autónomo dividido y preferencias permitidas de aspecto, idioma y anchura de paneles. Inventario.json conserva orden, tamaño y SHA para reconstruir PCM/bundle. No exporta configuración Git, hooks ni almacén de credenciales. Documentos, borradores, audio e historial pueden contener datos personales y secretos escritos por sus autores: la interfaz lo presenta como archivo privado.

Formato knownext.project2 con resumen tipado dataOnly y carpeta visible «Archivo KnowNext»; continúa la lectura de1. Las entradas archive solo se admiten bajo esa carpeta y con extensiones de datos previstas. Se mantienen límites128MiB totales,32MiB por archivo y10000 entradas; audio/historial se parten, sin eludir el total. Inventarios privados acotados, archivos regulares, rutas contenidas, sin abrir/copiar coordinación. Cambios de fuentes/inventario, sesión activa/enviando, colisión de carpeta, metadatos incompatibles o exceso de tamaño impiden entregar el conjunto. Git tiene límite de tiempo/salida/paquete, sin hooks ni red, y se rechazan repositorios dependientes/incompletos. Preferencias se proyectan por lista permitida; no se copia configuración IA/dispositivos.

Importar crea un proyecto nuevo, sin reemplazar originales. Borradores/audio/historial/preferencias del archivo se conservan como datos consultables: no se adoptan en almacenes activos ni se encola trabajo. El archivo no puede convertirse en plantilla, tanto en interfaz como en servicio. Un acuse repetido de importación conserva las ediciones posteriores del proyecto recibido. El formato no restaura por sí mismo la experiencia activa de historial/audio/preferencias; esa adopción revisada sigue pendiente. Tampoco incluye cambios aún sin persistir en el editor, sesiones sin proyecto asignado, papelera, cachés, recibos de operaciones, copias de conflictos ni todo el perfil.

Verificación dirigida: contrato real entre dos almacenes independientes conserva documento, borrador original/editable, transcripción y PCM de16MiB+2bytes en dos WAV; concatena el bundle y clona en repositorio temporal independiente con sus dos commits. Preferencias visuales conservadas y centinelas de credenciales/configuración Git excluidos; ningún almacén activo adoptado y fuentes intactas. Contratos de rechazos: selección, grabación pausada, colisión, formato futuro99, dataOnly contradictorio, tipo archive fuera de carpeta y conteos fuera de límites. Dieciséis casos frontend/SDK pasan (cuatro nuevos, doce afectados) y TypeScript correcto. Se reutiliza el transporte nativo sin nuevos comandos; no se repiten compilación Tauri, APK ni suites completas por este cambio interno.

Diálogo, hook y revisión reales con adaptadores controlados: opción inicial desmarcada, preparación explícita, revisión sin plantilla, alcance a demanda, entrega y confirmación de proyecto nuevo. Cuatro llamadas explícitas, una sola importación, sin errores ni red externa. Capturas505–509 inspeccionadas; pie visible y sin desbordamiento a320x560. El fixture visual no ejecuta entrega/selector nativo ni aceptación instalada; los contratos prueban por separado archivos temporales reales.
