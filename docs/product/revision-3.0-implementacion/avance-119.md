# Avance119 · Preferencias portables revisadas antes de aplicar

[Reporte visual](avance-119.html) · [Definición](bloque-119.md) · [Plan](plan.md).

Recuperación/Proyectos ofrece revisar las preferencias visuales encontradas en Archivo KnowNext/Preferencias.json. Se comparan valores actuales y del archivo, y se eligen por separado aspecto/idioma y anchos de paneles, inicialmente desmarcados. Aplicar requiere seleccionar, confirmar y disponer de la autoridad existente de transición crítica del espacio de trabajo. Antes se protege el trabajo abierto y se comprueban ajustes pendientes; después la aplicación recarga el estado observado. El proyecto consultado no se activa al abrir la revisión.

GET/POST /api/projects/:id/portable-preferences. Servicio Rust con formato knownext.portable-preferences1 estricto, sin campos adicionales ni applyAutomatically=true, lista visual permitida y límites32KiB de fuente/8MiB de configuración. Revisión SHA ligada a proyecto, ubicación canónica, bytes del archivo y configuración completa actual. Cambios/futuros/enlaces no se convierten en valores predeterminados escribibles. Se vuelven a comprobar las entradas inmediatamente antes de publicar; no es CAS frente a programas externos. Se actualizan solo las claves del grupo elegido y updatedAt; se conservan grupos/campos ajenos, IA y datos de trabajo. Si ya coinciden, no se escribe otra vez. La respuesta se comprueba contra la configuración observada.

Una confirmación perdida provoca consulta, nunca reenvío automático. Se exige una revisión nueva para otro intento. La aplicación cierra la recuperación y recarga el almacenamiento también ante resultado incierto, siguiendo la transición existente; el documento permanece protegido. El botón es de consulta cuando falta esa autoridad. Los campos exportados son idioma/tema/naranja/zoom/subrayado compatible y anchuras; no se adoptan IA, dispositivos ni otras preferencias.

Tres contratos Rust dirigidos pasan: grupo de aspecto sin cambiar layout/IA/campos propios, grupo layout sin cambiar aspecto, fuente/configuración cambiadas, falta de confirmación/selección, futuros/campos adicionales y archivo preservado; revisión repetida de valores coincidentes sin escritura. Seis casos frontend/SDK iniciales pasan; dos casos añadidos dirigidos verifican preflight rechazado sin llamada y acuse unchanged válido. TypeScript correcto. Sin suites completas ni nueva compilación/instalación nativa: se usa el despachador API existente, sin comandos nuevos.

Campaña App/Centro de Recuperación/Proyecto/diálogo/transición reales con adaptadores y persistencia web-dev controlados: comparación escritorio, selección de anchos a320x560, único cambio con acuse interrumpido, recarga y reapertura por navegación móvil con valores observados280/300px. Tres consultas, una sola aplicación explícita (aspecto false/layout true), documento conservado, sin errores/red externa/desbordamiento. Capturas513–516 inspeccionadas. La campaña no escribe la configuración nativa ni acredita instalación; los contratos prueban por separado almacenamiento temporal real.

Evidencia: output/v3-portable-preferences-contract.log; output/v3-portable-preferences-ui.log; output/v3-portable-preferences-extra-contracts.log; output/v3-portable-preferences-types.log; output/v3-portable-preferences-browser-evidence.json.
